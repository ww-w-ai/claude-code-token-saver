## 🛡️ Функция 1: Token Guardian

**Обнаруживает истечение cache и автоматически блокирует дорогую повторную отправку.**

TTL cache промптов в Claude Code — 1 час. Отойдите больше чем на час — cache истечёт. Следующее сообщение пересылает весь context по полной цене. При 900K token это $9 за один запрос.

Token Guardian отслеживает время последнего ответа. Если прошло более 3590 секунд (TTL минус 10-секундный буфер), промпт блокируется с предупреждением.

```
🚨 Кэш истёк (68м 23с простоя)

Кэш истёк. Продолжение отправит весь контекст заново.
Стоимость может значительно возрасти.

👉 /context — Проверить текущее использование контекста перед принятием решения
👉 /clear → /continue — Сбросить и восстановить предыдущий контекст (рекомендуется, минимальная стоимость)
👉 Отправить снова — Продолжить как есть (возникнет полная стоимость повторного кэширования)
```

Просто отправьте тот же промпт повторно после предупреждения — он пройдёт. Предупреждение срабатывает один раз за период простоя, поэтому не надоедает. Сообщения отображаются на 23 языках в зависимости от локали ОС.

**Результат:** Дорогие повторные кэширования предотвращаются автоматически. Никаких усилий.

## 🧠 Функция 2: Smart Session Architecture

**Установите — и оптимизация расходов включается автоматически.**

Большинство пользователей делают всё в Main session. Чтение файлов, генерация кода, запуск тестов. Каждый результат накапливается в context и пересылается с каждым сообщением. Session раздувается. Расходы взлетают.

Session Architect автоматически внедряет стратегию делегирования при старте session.

|                  | Main Session                      | SubTask                               |
| ---------------- | --------------------------------- | ------------------------------------- |
| Роль             | Проектирование, решения, ревью    | Реализация, генерация кода, multi-file |
| Cache tier       | 1 час (ephemeral_1h)              | 5 мин                                 |
| Cache write      | ＄10/MTok                          | ＄6.25/MTok                            |
| Размер context   | ~94K в среднем                    | ~33K в среднем                        |

Cache write в SubTask **на 37,5% дешевле**, чем в Main. Context тоже значительно меньше. Делегирование тяжёлой работы в SubTask резко снижает расходы.

**Результат:** Claude автоматически работает по экономичной схеме. Вам не нужно об этом думать.

## 🔄 Функция 3: /continue — Восстановление context

**Замена `/compact`. Ноль вызовов LLM. Ноль расходов на token.**

`/compact` отправляет весь context (~1M token) в LLM для сжатия в 3.3% резюме. Если cache истёк, одно это уже вызывает полное повторное кэширование. Потеря информации неизбежна.

`/continue` работает совершенно иначе. Он предварительно обрабатывает транскрипт предыдущей session и загружает напрямую. Без вызовов LLM. Без расходов. Оригинальный диалог восстанавливается как есть.

|                         | /compact                          | /continue                        |
| ----------------------- | --------------------------------- | -------------------------------- |
| Как работает            | Отправляет весь context в LLM для резюме | Предобрабатывает транскрипт, читает напрямую |
| Вызовы LLM              | Требуются (обычно 100K+ token)   | 0                                |
| Расход token            | Высокий                           | 0                                |
| Потеря информации       | Да (3.3% резюме)                  | Нет (оригинал сохранён)          |
| Скорость                | Десятки секунд                     | < 1 сек (даже файлы 60MB+)       |
| При истёкшем cache      | Дополнительные расходы на re-cache | Не влияет                        |
| Multi-session restore   | Невозможно                         | Поддерживается                   |

Использование: `/clear`, затем `/continue`. Появится список предыдущих session. Выберите нужную. Для быстрого восстановления: `/continue last`.

**Результат:** Возвращайтесь к предыдущей работе без расходов. Без потери информации.

## 📈 Usage Dashboard (/usage-view)

**Наконец-то ответ на вопрос: "Почему сработал rate limit?"**

До сих пор rate limit просто злил. Невозможно было понять причину. Какая session сожгла больше всего token? Когда произошёл скачок расходов? Какие паттерны есть в использовании? Всё невидимо.

`/usage-view` показывает всё. Интерактивный HTML-дашборд открывается в браузере, позволяя анализировать паттерны использования и находить причины скачков расходов. Без внешних зависимостей. Работает автономно. Можно передать как файл.

Что включено:

- Дневные / почасовые / понедельные тренды расходов — определите, когда вы сжигаете больше всего token
- Разбивка token (input, output, cache write, cache read) — смотрите, что вызывает расходы
- Анализ стоимости по session — определите, какие задачи были дорогими
- Таймлайн 5-часового окна (подписчики Max Plan) — отследите причины rate limit
- AI-анализ с рекомендациями — интерпретирует данные и предлагает улучшения
- 23 языка (RTL включая; графики/таблицы остаются LTR)

```
/usage-view                  # Всё время, все проекты
/usage-view current          # Только текущее 5-часовое окно
```

## ✂️ Функция 5: /setup-git-lite — Обрезаем встроенные инструкции по Git в CC

**Скрытые 2 200 token за session, о которых вы не знали.**

### Открытие

12 апреля 2026 года в [GitHub issue](https://github.com/anthropics/claude-code/issues/47107) выяснилось, что встроенная настройка `includeGitInstructions` в Claude Code незаметно сжигает token при каждой session. Независимое воспроизведение через [этот gist (spilist)](https://gist.github.com/spilist/b0db92a859192f5ec6199d3f35a81b98) подтвердило цифры: **+6 031 token в cache writes** за session после каждого git commit, **+1 690 token в cache reads** при каждом API-вызове.

### Анализ исходников CC — куда уходят token

Мы отследили token до двух независимых точек внедрения в исходном коде Claude Code (v2.1.88):

**1. Снимок `gitStatus` (~500 tok) — system prompt**
- `context.ts:36-111` `getGitStatus()` собирает ветку + основную ветку + user.name + полный статус (до 2000 символов) + **последние 5 коммитов**
- Объединяется и добавляется к system prompt через `appendSystemContext` (`utils/api.ts:437`)
- Каждый новый коммит, каждый изменённый файл, каждое переключение ветки меняет текст → инвалидация prefix cache

**2. Инструкции рабочего процесса commit/PR (~1 700 tok) — описание Bash-инструмента**
- `tools/BashTool/prompt.ts:53` добавляет 60+ строк протокола безопасности, пошаговую процедуру commit, примеры HEREDOC и шаблоны PR к описанию инструмента `Bash`
- Кешируется вместе с system prompt, но передаётся как параметр `tools[]`

### Почему это дорого

Структура cache (`utils/api.ts:321` `splitSysPromptPrefix`) имеет три пути в зависимости от наличия активных MCP-инструментов:

- **Path A** (MCP активен — большинство пользователей): `gitStatus` находится внутри блока `cacheScope: 'org'`. Любое изменение → весь блок пересчитывается при следующем старте session → 6K tok промах `cache_create`.
- **Path B** (без MCP): `gitStatus` попадает в динамический блок `cacheScope: null`, то есть пересылается как свежие `input_tokens` при каждом API-вызове — без промаха cache, но и без экономии cache.
- **Path C** (сторонний провайдер / экспериментальные бета-функции отключены): то же, что Path A.

В типичных интерактивных session инструкции commit/PR (1,7K tok) накапливаются **при каждом API-вызове** через `cache_read`. За 100-вызовную session по ценам Opus 4.7 это примерно **$0,08 за session** только за инструкции, которые обучение Claude в основном уже охватывает.

### Как cc-token-saver справляется с этим

`/setup-git-lite` отключает нативный путь и внедряет **компактную замену на 280 token** через хук SessionStart. Мы сохранили именно то, что переопределяет стандартное поведение Claude (правила безопасности), и убрали всё, что Claude уже знает из обучения (пошаговые рабочие процессы, шаблоны PR, паттерны использования gh).

**Сохранено — 11 критических правил переопределения** (те, которые переключают стандартную готовность Claude помочь в осторожность):
- Никогда не делать commit/push/amend/PR/tag/merge без явного запроса пользователя
- Никогда не пропускать хуки, не делать force-push в main/master, не выполнять деструктивные операции, не изменять git config
- Никогда не делать commit файлов, соответствующих `.env`, `credentials`, `*.pem`, `secret.*`
- Избегать `git add -A` / `git add .`
- HEREDOC для многострочных сообщений commit + трейлер `Co-Authored-By: Claude`
- Никогда не использовать интерактивные флаги (-i), никаких пустых коммитов
- Если pre-commit hook падает → создать НОВЫЙ commit (не `--amend`)

**Убрано** — пошаговый рабочий процесс commit (3 шага), пошаговый рабочий процесс PR (3 шага), шаблон заголовка/тела PR, ссылки на команду `gh`, предупреждение о флаге `-uall`, предупреждение о `--no-edit` с rebase, ограничение `NEVER use TodoWrite or Agent tools during commit`. Это словесная избыточность рабочего процесса, которую Claude корректно составляет из обучения самостоятельно.

**Добавлено** — компактная строка состояния git: ветка + короткий sha HEAD + тема + текущий статус (до 20 изменённых файлов, иначе количество). Без списка последних коммитов (Claude может выполнить `git log` по запросу).

### Ожидаемая экономия (цены Opus 4.7: $25/MTok вывод, $5/MTok ввод, $0,50/MTok cache read)

| Элемент | Исходно | С setup-git-lite | Экономия |
| ------- | ------- | ---------------- | -------- |
| Загрузка system prompt (за новую session) | ~2 200 tok cache_create | ~280 tok cache_create | ~1 920 tok |
| Повторные вызовы в той же session | ~1 700 tok cache_read/вызов | ~280 tok cache_read/вызов | ~1 420 tok/вызов |
| Session на 100 вызовов (Opus 4.7) | — | — | **~$0,11 экономии** |
| 20 session/день × 22 рабочих дня | — | — | **~$48 экономии/мес** |

### Использование

```bash
/setup-git-lite status     # Только чтение — текущее состояние + что изменится
/setup-git-lite install    # Отключить нативный CC + включить наш минимальный хук
/setup-git-lite revert     # Восстановить настройки по умолчанию (агрессивно; см. ниже)
/setup-git-lite dismiss    # Заглушить периодический совет-подсказку
/setup-git-lite undismiss  # Снова включить подсказку
/setup-git-lite help       # Полное описание использования
```

### Семантика install

`install` изменяет **два** места для надёжности:

1. `~/.claude/settings.json` — добавляет `"includeGitInstructions": false`
2. Профиль оболочки (`~/.zshrc`, `~/.bashrc` и т.д.) — добавляет маркерный блок с экспортом `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`

Каждого из них достаточно для отключения нативного CC; мы устанавливаем оба, чтобы переопределение переменной среды случайно не включило нативное поведение снова. Изменение оболочки вступает в силу только в новых оболочках.

### Семантика revert — агрессивная

`revert` **удаляет ВСЕ экспорты `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` из профиля оболочки**, включая те, что вы могли добавить вручную до установки этого skill. Это намеренно — вы запустили `revert`, значит мы восстанавливаем чистые настройки по умолчанию. Перед этим всегда создаётся резервная копия профиля оболочки с временной меткой.

Если переменная среды нужна вам по другим причинам, запишите её перед запуском `revert` и добавьте снова после.

### Перед удалением cc-token-saver

**Сначала запустите `/setup-git-lite revert`**, иначе у вас останется `includeGitInstructions: false` в settings.json без заменяющего хука (Claude вообще не получит никаких инструкций по git). В Claude Code в настоящее время нет хука жизненного цикла для удаления плагина, поэтому мы не можем автоматизировать это.

### Компромиссы

Что вы теряете (и почему это обычно нормально):
- Claude больше не получает предварительно вычисленный `git status` / `git log -n 5` при старте session. Если вы спросите «что изменилось?» в новой session, Claude выполнит эти команды сам (один лишний tool call, ~300 tok).
- Claude больше не видит каноническую 3-шаговую процедуру commit от CC. По нашему тестированию на сотнях commit-потоков знания уровня обучения справляются с критическими случаями (форматирование HEREDOC, без `--amend`, без force-push), потому что мы сохраняем их как явные правила.
- Шаблон тела PR (`## Summary` + `## Test plan`) не внедряется. Если вам важен именно этот формат, добавьте его в CLAUDE.md вашего проекта.

### Баннер-рекомендация

Когда нативные инструкции git CC всё ещё активны на вашей машине, cc-token-saver показывает одноабзацную подсказку при старте session **~20% времени** (а также в выводах `/usage-view` и `/report-limit`). Отключите навсегда с помощью `/setup-git-lite dismiss`.

## 💡 Как на самом деле работает cache

Claude Code отправляет всю историю диалога модели при каждом API-вызове. «API-вызов» — это не «одно сообщение, которое вы набрали». Один промпт вызывает внутренние вызовы инструментов — Grep, Read, Edit, Write — и каждый из них является отдельным API-вызовом. Один промпт легко вызывает 10+ API-вызовов.

Cache промптов снижает эти расходы на 90%. Но у cache есть срок жизни.

|                     | Main Session                          | SubTask                                |
| ------------------- | ------------------------------------- | -------------------------------------- |
| Cache TTL           | 1 час (ephemeral_1h)                  | 5 мин                                  |
| Cache write         | ＄10/MTok                              | ＄6.25/MTok                             |
| Cache read          | ＄0.50/MTok                            | ＄0.50/MTok                             |
| При истечении cache | Весь context пересылается по полной цене | Минимальное влияние (context мал)      |

Даже при живом cache расходы накапливаются. Вот экстремальный сценарий, показывающий разницу.

### Сценарий: Полный день кодинга (3ч утро → 2ч обед/встреча → 3ч после обеда)

Условия: цены Opus 4, 1 промпт в минуту, ~5 API-вызовов на промпт (~300 вызовов/час).

#### ❌ Без cc-token-saver

Основная работа идёт в Main session. Context растёт быстро.

| Фаза        | Ситуация                          | Размер context              | Стоимость                              |
| ----------- | --------------------------------- | --------------------------- | -------------------------------------- |
| Утро 3ч     | Кодинг (в основном Main)          | 100K → 600K (ср. 350K)     | 900 вызовов × 350K × ＄0.50/M = ＄157.50 |
| Обед/встреча | Отсутствие 2 часа                 | —                           | —                                      |
| Возвращение | Cache истёк → полная пересылка    | 600K по полной цене         | 600K × ＄5/M + 600K × ＄10/M = ＄9       |
| Возвращение | /compact (сжатие)                 | 600K → отправлено в LLM     | 600K × ＄0.50/M + вывод summary = ~＄1.50 |
| После обеда 3ч | Продолжение кодинга (context растёт) | 100K → 600K (ср. 350K)  | 900 вызовов × 350K × ＄0.50/M = ＄157.50 |
|             | Итого                             |                             | ~＄326                                  |

> При таком уровне использования вы почти наверняка попадёте под 5-часовой rate limit. **Расходы — это полбеды, настоящая проблема в том, что работа встаёт намертво. Именно в этот момент Claude Code замолкает.**

#### ✅ С cc-token-saver

Тяжёлая работа делегируется SubTask. Main занимается только проектированием и решениями.

| Фаза        | Ситуация                                     | Размер context               | Стоимость                          |
| ----------- | -------------------------------------------- | ---------------------------- | ---------------------------------- |
| Утро 3ч     | Кодинг (Main: проектирование, SubTask: реализация) | Main 100K → 300K (ср. 200K) | 900 вызовов × 200K × ＄0.50/M = ＄90 |
| Обед/встреча | Отсутствие 2 часа                            | —                            | —                                  |
| Возвращение | ⚡ Token Guardian блокирует → /clear + /continue | —                           | ＄0 (без вызовов LLM)              |
| После обеда 3ч | Продолжение кодинга                         | Main 100K → 300K (ср. 200K) | 900 вызовов × 200K × ＄0.50/M = ＄90 |
|             | Итого                                        |                              | ~＄180                              |

#### 💰 Результат

> **＄326 → ＄180. ＄146 экономии в день (45%).**
>
> Дело не только в расходах. Меньше token за то же время означает, что **вы не попадаете под rate limit и можете продолжать работать.** Вот в чём настоящая разница.

```
[Старт session]

    ├─ Session Architect → Автоматически внедряет паттерн делегирования SubTask

[Работа]
    │
    ├─ Status Line → Мониторинг расходов/context/rate limit в реальном времени
    │                  Мгновенное оповещение при входе в зону предупреждения
    │
[1+ час простоя]
    │
    ├─ Token Guardian → Обнаруживает истечение cache, блокирует до пересылки
    │
[Перезапуск session]
    │
    └─ /continue → Восстанавливает предыдущий context без расходов (без вызовов LLM)
```

## 💡 Советы

### Поймите cache — и увидите, куда уходят деньги

- **1 промпт ≠ 1 API-вызов.** Каждый раз, когда Claude вызывает Grep, Read или Edit, весь context пересылается заново. Один промпт легко вызывает 10+ API-вызовов. Пишите чёткие промпты, чтобы снизить ненужные tool call и сократить расходы.
- **Таймер cache сбрасывается от последнего API-вызова, а не от вашего последнего промпта.** Продолжайте работать — и cache никогда не истечёт. Опасность — в перерыве. Token Guardian автоматически блокирует один раз, и при возвращении вы можете выбрать: сбросить context или продолжить как есть.
- **Размер context = множитель стоимости.** Один и тот же API-вызов при 200K vs 800K стоит в 4 раза дороже. Когда status line [CTX] пересекает 35% (🟡) — это сигнал больше делегировать в SubTask.

### Привычки, снижающие расходы

- **Держите CLAUDE.md компактным.** Он загружается в system prompt при каждом API-вызове. Каждая строка стоит денег.
- **Делегируйте тяжёлую работу в SubTask.** Генерация кода, multi-file правки, запуск тестов — не для Main. SubTask имеют меньший context и более дешёвый cache tier.
- **Отсутствуете 1+ час?** `/clear` → вернитесь → `/continue`. Context восстановлен за $0.
- **[5H] выше 70% (🟡)?** Замедлитесь. Переключитесь на лёгкие задачи ревью или увеличьте делегирование в SubTask, чтобы снизить количество API-вызовов Main.
- **Используйте `/btw` для побочных вопросов.** Он не попадает в историю диалога, поэтому context остаётся компактным.
