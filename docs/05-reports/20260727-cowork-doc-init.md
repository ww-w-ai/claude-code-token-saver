- **Scope**: first-time fit of this repo to the `cowork-doc-sync` taxonomy
- **Outcome**: minimal adoption — 1 file relocated, 2 folders created, local convention declared

## Finding: this repo is a plugin, not a doc project

An inventory of every tracked markdown file found that almost none of it is internal
documentation. It is **product surface** — text users read on GitHub, or text Claude reads at
runtime. Relocating any of it breaks something:

| Candidate | Reality | Action |
|---|---|---|
| `docs/images/` (13 files) | Referenced by **all 23 README locales** | Leave — a move breaks 23 files |
| `guides/` (25 files) | Reader-facing publications linked from README; paths are public URLs | Leave |
| `hooks/session-architecture.md` | Injected into the user's session by a hook — product content | Leave |
| `skills/*/SKILL.md` | The skills' executable instructions (the LLM is the runtime) | Leave |
| `docs/commit-log/` | Generated by `/cowork-commit`; outside the numbering by contract §4 | Leave |
| `docs/transcript-reference.md` | Describes CC's transcript format — stable external background | **→ `docs/00-reference/`** |
| `docs/v1.4.1-*` (7 files), `docs/competitor-analysis/` | Untracked; kept local by the owner's decision (raw session transcript, 14MB, contains real conversation content) | Not in scope |

Net taxonomy material: **one file**. Scaffolding all eight standard folders would have left seven
empty, so only the two with real content were created (`00-reference`, `05-reports`).

## Finding: the real risk was release-surface drift, not filing

The change that triggered this run — a single hook fix — required aligning **27 files across two
repositories**: 23 README locales, `CHANGELOG.md`, `CLAUDE.md`, `.claude-plugin/plugin.json`, and
`marketplace.json` in the separate marketplace repo. None of that was written down anywhere. A
missed surface ships a version mismatch to users, and content-diffing cannot catch it because the
files are individually valid.

`docs/CONVENTION.md` §3 now enumerates those surfaces with copy-pasteable verification commands.

Secondary finding: **git tags stopped at `v2.2.0`** while releases continued to 2.4.1. Any check
that treats a tag as proof of release will misreport. The convention was corrected to verify
against the marketplace entry instead. Whether to resume tagging is an open call for the owner.
