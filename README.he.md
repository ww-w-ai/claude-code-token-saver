## 🛡️ פיצ'ר 1: Token Guardian

**מזהה פקיעת cache וחוסם אוטומטית שליחות מחדש יקרות.**

ה-TTL של prompt cache ב-Claude Code הוא שעה. אם נעדרת יותר משעה, ה-cache פג. ההודעה הבאה שלך שולחת את כל ה-context מחדש במחיר מלא. ב-900K token, זה $9 בפעולה אחת.

Token Guardian עוקב מתי התקבלה התשובה האחרונה. אם עברו יותר מ-3,590 שניות (TTL פחות 10 שניות מרווח ביטחון), הוא חוסם את ה-prompt ומציג אזהרה.

```
🚨 המטמון פג תוקף (68 דקות 23 שניות ללא פעילות)

מטמון ההנחיה פג תוקף. המשך ישלח מחדש את כל ההקשר.
העלות עלולה לעלות משמעותית.

👉 /context — בדוק את השימוש הנוכחי בהקשר לפני קבלת החלטה
👉 /clear → /continue — איפוס ואז שחזור ההקשר הקודם (מומלץ, עלות מינימלית)
👉 שליחה מחדש — המשך כפי שזה (עלות מלאה של מטמון מחדש תיגרם)
```

פשוט שלח מחדש את אותו prompt אחרי האזהרה — הוא עובר. האזהרה מופעלת רק פעם אחת לכל תקופת חוסר פעילות, כך שהיא לא מטרידה. הודעות אזהרה מוצגות ב-23 שפות בהתאם ל-locale של מערכת ההפעלה שלך.

**תוצאה:** עלויות cache מחדש יקרות נמנעות אוטומטית. ללא מאמץ.

## 🧠 פיצ'ר 2: Smart Session Architecture

**מתקינים, ודפוסי עבודה מותאמי עלות נכנסים לפעולה אוטומטית.**

רוב המשתמשים עושים הכל ב-Main session. קריאת קבצים, יצירת קוד, הרצת טסטים. כל פלט נערם ל-context ונשלח מחדש עם כל הודעה. ה-session מתנפח. העלויות מצטברות.

Session Architect מזריק אוטומטית אסטרטגיית האצלה בתחילת ה-session.

|                  | Main Session                      | SubTask                               |
| ---------------- | --------------------------------- | ------------------------------------- |
| תפקיד            | עיצוב, החלטות, סקירה             | מימוש, יצירת קוד, עריכת מספר קבצים   |
| שכבת cache       | שעה (ephemeral_1h)                | 5 דקות                                |
| עלות כתיבת cache | ＄10/MTok                          | ＄6.25/MTok                            |
| גודל context     | ~94K ממוצע                        | ~33K ממוצע                            |

ל-SubTask יש **כתיבת cache זולה ב-37.5%** מ-Main. גם ה-context קטן בהרבה. האצלת עבודה כבדה ל-SubTask מפחיתה עלויות באופן משמעותי.

**תוצאה:** Claude עובד אוטומטית בדפוס חסכוני. לא צריך לחשוב על זה.

## 🔄 פיצ'ר 3: /continue — שחזור Context

**מחליף את `/compact`. אפס קריאות LLM. אפס עלות token.**

`/compact` שולח את כל ה-context (~1M token) ל-LLM כדי לדחוס אותו לסיכום של 3.3%. אם ה-cache פג, זה לבד מפעיל cache מחדש מלא. אובדן מידע בלתי נמנע.

`/continue` לוקח גישה אחרת לחלוטין. הוא מעבד מראש את תמלול ה-session הקודם וטוען אותו ישירות. ללא קריאת LLM. ללא עלות. השיחה המקורית משוחזרת כמו שהיא.

|                         | /compact                          | /continue                        |
| ----------------------- | --------------------------------- | -------------------------------- |
| אופן הפעולה             | שולח context מלא ל-LLM לסיכום    | מעבד מראש את התמלול, קורא ישירות |
| קריאות LLM              | נדרשת (בדרך כלל 100K+ token)     | 0                                |
| עלות token              | גבוהה                            | 0                                |
| אובדן מידע              | כן (סיכום 3.3%)                  | אין (מקור נשמר)                  |
| מהירות עיבוד             | עשרות שניות                      | < 1 שנייה (גם קבצים של 60MB+)   |
| כאשר cache פג           | עלות cache מחדש מלאה מעל         | אין השפעה                        |
| שחזור רב-session         | לא אפשרי                        | נתמך                             |

שימוש: `/clear` ואז `/continue`. תראה רשימת session קודמים. בחר אחד לשחזור. לשחזור מהיר: `/continue last`.

**תוצאה:** חזרה לעבודה קודמת בעלות אפס. ללא אובדן מידע.

## 📈 לוח בקרה (/usage-view)

**סוף סוף תשובה ל: "למה קיבלתי rate limit?"**

עד עכשיו, לפגוע ב-rate limit רק עצבן. אין דרך לדעת את הסיבה. איזה session שרף הכי הרבה token? מתי העלויות זינקו? אילו דפוסים קיימים בשימוש שלך? הכל בלתי נראה.

`/usage-view` מציג הכל. לוח בקרה HTML אינטראקטיבי נפתח בדפדפן, ומאפשר לנתח דפוסי שימוש ולאתר את מקור זינוקי העלות. ללא תלויות חיצוניות. עובד עצמאית. ניתן לשיתוף כקובץ.

מה כלול:

- מגמות עלות יומיות / שעתיות / לפי יום בשבוע — זהה מתי אתה שורף הכי הרבה token
- פירוט token (קלט, פלט, כתיבת cache, קריאת cache) — ראה מה מניע את העלויות
- ניתוח עלות לפי session — אתר אילו משימות היו יקרות
- ציר זמן חלון 5 שעות (מנויי Max Plan) — עקוב אחרי טריגרים של rate limit
- ניתוח תובנות מונחה AI — מפרש נתונים ומציע שיפורים
- 23 שפות נתמכות (כולל RTL; תרשימים/טבלאות נשארים LTR)

```
/usage-view                  # כל הזמנים, כל הפרויקטים
/usage-view current          # חלון 5 שעות נוכחי בלבד
/usage-view last 7 days      # 7 ימים אחרונים
/usage-view locale he        # עברית
```

## ✂️ פיצ'ר 5: /setup-git-lite — קיצוץ הוראות Git המובנות של CC

**2,200 token נסתרים לכל session שלא ידעת שאתה משלם עליהם.**

### הגילוי

ב-2026-04-12, [GitHub issue](https://github.com/anthropics/claude-code/issues/47107) חשף שההגדרה המובנית `includeGitInstructions` של Claude Code שורפת token בשקט בכל session. שחזור עצמאי דרך [gist זה (spilist)](https://gist.github.com/spilist/b0db92a859192f5ec6199d3f35a81b98) אישר את המספרים: **+6,031 token בכתיבות cache** לכל session אחרי כל git commit, **+1,690 token בקריאות cache** בכל קריאת API.

### ניתוח קוד CC — לאן הולכים ה-token

עקבנו אחרי ה-token לשתי נקודות הזרקה עצמאיות בקוד המקור של Claude Code (v2.1.88):

**1. תמונת מצב gitStatus (~500 tok) — system prompt**
- `context.ts:36-111` — `getGitStatus()` אוסף branch + main branch + user.name + סטטוס מלא (עד 2000 תווים) + **5 commits אחרונים**
- מוצמד ומוסף ל-system prompt דרך `appendSystemContext` (`utils/api.ts:437`)
- כל commit חדש, כל קובץ שונה, כל החלפת branch משנה את הטקסט → ביטול prefix cache

**2. הוראות workflow לcommit/PR (~1,700 tok) — תיאור כלי Bash**
- `tools/BashTool/prompt.ts:53` מצמיד 60+ שורות של פרוטוקול בטיחות, נוהל commit שלב-אחר-שלב, דוגמאות HEREDOC ותבניות יצירת PR לתיאור הכלי `Bash`
- נשמר ב-cache לצד ה-system prompt, אך נשלח כפרמטר `tools[]`

### למה זה יקר

מבנה ה-cache (`utils/api.ts:321` — `splitSysPromptPrefix`) כולל שלושה נתיבים בהתאם לכך שיש לך כלי MCP פעילים:

- **Path A** (MCP פעיל — רוב המשתמשים): `gitStatus` יושב בתוך בלוק `cacheScope: 'org'`. כל שינוי → כל הבלוק נכתב מחדש ב-cache בתחילת session הבא → 6K tok `cache_create` miss.
- **Path B** (ללא MCP): `gitStatus` עובר לבלוק דינמי `cacheScope: null`, כלומר נשלח מחדש כ-`input_tokens` טריים בכל קריאת API — ללא cache miss, אך גם ללא חיסכון ב-cache.
- **Path C** (ספק 3P / beta ניסיוניים מבוטלים): זהה ל-Path A.

ב-sessions אינטראקטיביים טיפוסיים, הוראות commit/PR (1.7K tok) מצטברות **בכל קריאת API** דרך `cache_read`. על פני session של 100 קריאות במחיר Opus 4.7, זה בערך **$0.08 לכל session** רק בשביל הוראות שהאימון של Claude כבר מכסה ברובן.

### כיצד cc-token-saver מטפל בזה

`/setup-git-lite` משבית את הנתיב המובנה ומזריק **תחליף מצומצם של 280 token** דרך SessionStart hook. שמרנו בדיוק את הדברים שעוקפים את ההתנהגות ברירת המחדל של Claude (כללי בטיחות), והשמטנו את כל מה ש-Claude כבר יודע מהאימון (workflows שלב-אחר-שלב, תבניות PR, דפוסי שימוש ב-gh).

**נשמר — 11 כללי override קריטיים** (אלה שהופכים את האדיבות ברירת המחדל של Claude לזהירות):
- לעולם אל תבצע commit/push/amend/PR/tag/merge ללא בקשה מפורשת מהמשתמש
- לעולם אל תדלג על hooks, תדחוף בכוח ל-main/master, תריץ פעולות הרסניות, תשנה את תצורת git
- לעולם אל תבצע commit לקבצים התואמים `.env`, `credentials`, `*.pem`, `secret.*`
- הימנע מ-`git add -A` / `git add .`
- HEREDOC להודעות commit מרובות שורות + trailers של `Co-Authored-By: Claude`
- לעולם אל תשתמש בדגלים אינטראקטיביים (-i), אין commits ריקים
- אם pre-commit hook נכשל → צור commit חדש (לא `--amend`)

**הושמט** — workflow commit שלב-אחר-שלב (3 שלבים), workflow PR שלב-אחר-שלב (3 שלבים), תבנית כותרת/גוף PR, הפניות לפקודות `gh`, אזהרת דגל `-uall`, אזהרת `--no-edit` עם rebase, אילוץ `NEVER use TodoWrite or Agent tools during commit`. אלה הם פירוט workflow שClaude מרכיב נכון מהאימון לבד.

**נוסף** — שורת מצב git קומפקטית: branch + HEAD short-sha + subject + סטטוס נוכחי (עד 20 קבצים שונים, אחרת ספירה). ללא רשימת commits אחרונים (Claude יכול להריץ `git log` לפי דרישה).

### שימוש

```bash
/setup-git-lite status     # אבחון קריאה בלבד — מצב נוכחי + מה ישתנה
/setup-git-lite install    # השבת CC native + הפעל hook מינימלי שלנו
/setup-git-lite revert     # שחזר ברירת מחדל (אגרסיבי; ראה למטה)
/setup-git-lite dismiss    # השתק את טיפ ההמלצה המזדמן
/setup-git-lite undismiss  # הפעל מחדש את הטיפ
/setup-git-lite help       # שימוש מלא
```

### סמנטיקת התקנה

`install` משנה **שני** מקומות לצורך אמינות:

1. `~/.claude/settings.json` — מוסיף `"includeGitInstructions": false`
2. פרופיל shell (`~/.zshrc`, `~/.bashrc`, וכו') — מצמיד בלוק marker שמייצא `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`

כל אחד לבד מספיק כדי להשבית את ה-CC native; אנו מגדירים את שניהם כדי שעקיפה דרך משתנה סביבה לא תפעיל מחדש בטעות את ההתנהגות המובנית. שינוי ה-shell נכנס לתוקף רק ב-shells חדשים.

### סמנטיקת revert — אגרסיבי

`revert` **מסיר את כל ייצואי `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS` מפרופיל ה-shell שלך**, כולל כאלה שאולי הוספת ידנית לפני התקנת ה-skill הזה. זה מכוון — הרצת `revert`, אז אנו משחזרים את ברירת המחדל הנקייה. אנו תמיד יוצרים גיבוי עם חותמת זמן של פרופיל ה-shell תחילה.

אם אתה צריך את משתנה הסביבה מסיבות לא קשורות, רשום אותו לפני הרצת `revert` והוסף אותו מחדש לאחר מכן.

### לפני הסרת cc-token-saver

**הרץ `/setup-git-lite revert` תחילה**, אחרת תישאר עם `includeGitInstructions: false` ב-settings.json שלך ללא hook חלופי (Claude לא יקבל שום הנחיות git). ל-Claude Code כרגע אין plugin uninstall lifecycle hook, לכן לא נוכל לבצע אוטומציה של זה.

### פשרות

מה אתה מפסיד (ולמה זה בדרך כלל בסדר):
- Claude כבר לא מקבל `git status` / `git log -n 5` מחושב מראש בתחילת session. אם תשאל "מה השתנה?" ב-session חדש, Claude יריץ את הפקודות האלה בעצמו (קריאת כלי אחת נוספת, ~300 tok).
- Claude כבר לא רואה את נוהל ה-commit ב-3 שלבים הקנוני של CC. בבדיקות שלנו על פני מאות זרימות commit, ידע ברמת אימון מטפל במקרים הקריטיים (עיצוב HEREDOC, לא `--amend`, לא force-push) כי אנו שומרים אלה כחוקים מפורשים.
- תבנית גוף PR (`## Summary` + `## Test plan`) לא מוזרקת. אם אכפת לך בדיוק מהפורמט הזה, שים אותו ב-CLAUDE.md של הפרויקט שלך.

### באנר המלצה

כשהוראות git המובנות של CC עדיין פעילות על המחשב שלך, cc-token-saver מציג טיפ של פסקה אחת בתחילת session **~20% מהזמן** (בנוסף בפלטי `/usage-view` ו-`/report-limit`). דחה לצמיתות עם `/setup-git-lite dismiss`.

## 💡 איך Cache באמת עובד

Claude Code שולח את כל היסטוריית השיחה למודל בכל קריאת API. "קריאת API" זה לא "הודעה אחת שהקלדת". prompt בודד מפעיל קריאות כלים פנימיות — Grep, Read, Edit, Write — וכל אחת היא קריאת API נפרדת. prompt אחד יכול בקלות לגרום ל-10+ קריאות API.

prompt cache מפחית את העלות הזו ב-90%. אבל ל-cache יש משך חיים.

|                     | Main Session                          | SubTask                                |
| ------------------- | ------------------------------------- | -------------------------------------- |
| Cache TTL           | שעה (ephemeral_1h)                    | 5 דקות                                 |
| כתיבת cache         | ＄10/MTok                              | ＄6.25/MTok                             |
| קריאת cache         | ＄0.50/MTok                            | ＄0.50/MTok                             |
| כשה-cache פג        | כל ה-context נשלח מחדש במחיר מלא     | השפעה נמוכה (context קטן)              |

גם עם cache פעיל, עלויות מצטברות. הנה תרחיש קיצוני שמדגים את ההבדל.

### תרחיש: יום קידוד מלא (3 שעות בוקר → 2 שעות הפסקה/ישיבה → 3 שעות אחה"צ)

תנאים: תמחור Opus 4, prompt אחד לדקה, ~5 קריאות API לכל prompt (~300 קריאות/שעה).

#### ❌ ללא cc-token-saver

רוב העבודה קורית ב-Main session. ה-context גדל מהר.

| שלב          | מצב                                | גודל context               | עלות                                   |
| ------------ | ---------------------------------- | -------------------------- | -------------------------------------- |
| בוקר 3 שעות  | קידוד (בעיקר ב-Main)              | 100K → 600K (ממוצע 350K)   | 900 קריאות × 350K × ＄0.50/M = ＄157.50  |
| הפסקה/ישיבה  | לא ליד המחשב 2 שעות               | —                          | —                                      |
| חזרה         | cache פג → שליחה מחדש מלאה         | 600K מחיר מלא              | 600K × ＄5/M + 600K × ＄10/M = ＄9       |
| חזרה         | /compact (סיכום)                   | 600K → נשלח ל-LLM          | 600K × ＄0.50/M + פלט סיכום = ~＄1.50    |
| אחה"צ 3 שעות | קידוד ממשיך (context צומח מחדש)    | 100K → 600K (ממוצע 350K)   | 900 קריאות × 350K × ＄0.50/M = ＄157.50  |
|              | סה"כ                               |                            | ~＄326                                  |

> ברמת שימוש כזו, סביר שתפגע ב-rate limit של חלון 5 השעות. **העלות גרועה, אבל הבעיה האמיתית היא שהעבודה שלך נעצרת לחלוטין. זה הרגע המדויק שבו Claude Code נכבה.**

#### ✅ עם cc-token-saver

עבודה כבדה מואצלת ל-SubTask. Main מטפל בעיצוב/החלטות בלבד.

| שלב          | מצב                                           | גודל context                | עלות                               |
| ------------ | --------------------------------------------- | --------------------------- | ---------------------------------- |
| בוקר 3 שעות  | קידוד (Main: עיצוב, SubTask: מימוש)            | Main 100K → 300K (ממוצע 200K) | 900 קריאות × 200K × ＄0.50/M = ＄90 |
| הפסקה/ישיבה  | לא ליד המחשב 2 שעות                           | —                           | —                                  |
| חזרה         | ⚡ Token Guardian חוסם → /clear + /continue    | —                           | ＄0 (ללא קריאות LLM)               |
| אחה"צ 3 שעות | קידוד ממשיך                                    | Main 100K → 300K (ממוצע 200K) | 900 קריאות × 200K × ＄0.50/M = ＄90 |
|              | סה"כ                                           |                             | ~＄180                              |

#### 💰 תוצאה

> **＄326 → ＄180. ＄146 חיסכון ליום (45%).**
>
> זה לא רק עניין של עלות. פחות token באותו זמן אומר ש**לא תפגע ב-rate limit ותוכל להמשיך לעבוד.** זה ההבדל האמיתי.

### איפה cc-token-saver נכנס לפעולה

```
[התחלת Session]
    │
    ├─ Session Architect → מזריק אוטומטית דפוס האצלה ל-SubTask
    │                       שומר על context של Main מתחת ל-250K
    │
[עבודה]
    │
    ├─ Status Line → ניטור עלות/context/rate limit בזמן אמת
    │                  התראה מיידית בכניסה לאזור אזהרה
    │
[1+ שעה ללא פעילות]
    │
    ├─ Token Guardian → מזהה פקיעת cache, חוסם לפני שליחה
    │
[הפעלה מחדש של Session]
    │
    └─ /continue → משחזר context קודם בעלות אפס (ללא קריאות LLM)
```

## 💡 טיפים

### תבין cache ותראה לאן הכסף הולך

- **prompt אחד ≠ קריאת API אחת.** בכל פעם ש-Claude קורא ל-Grep, Read, או Edit, כל ה-context נשלח מחדש. prompt בודד מפעיל בקלות 10+ קריאות API. כתוב prompt ברורים כדי להפחית קריאות כלים מיותרות ולחסוך עלויות.
- **טיימר ה-cache מתאפס מקריאת ה-API האחרונה, לא מה-prompt האחרון שלך.** תמשיך לעבוד וה-cache לעולם לא יפוג. הסכנה היא לצאת. Token Guardian חוסם אוטומטית פעם אחת, כך שכשתחזור תוכל לבחור: אפס context או המשך כרגיל.
- **גודל context = מכפיל עלות.** אותה קריאת API ב-200K לעומת 800K עולה פי 4. כשה-status line [CTX] חוצה 35% (🟡), זה הסימן להאציל יותר ל-SubTask.

### הרגלים שחוסכים עלויות

- **שמור על CLAUDE.md רזה.** הוא נטען ל-system prompt בכל קריאת API. כל שורה עולה כסף.
- **האצל עבודה כבדה ל-SubTask.** יצירת קוד, עריכת מספר קבצים, הרצת טסטים לא שייכים ל-Main. ל-SubTask יש context קטן יותר ושכבת cache זולה יותר.
- **נעדרת שעה+?** `/clear` → חזור → `/continue`. ה-context משוחזר ב-$0.
- **[5H] מעל 70% (🟡)?** האט. עבור למשימות סקירה קלות או הגבר האצלה ל-SubTask כדי להפחית את מספר קריאות ה-API של Main.
- **השתמש ב-`/btw` לשאלות צדדיות.** זה לא נכנס להיסטוריית השיחה, כך שה-context שלך נשאר רזה.
