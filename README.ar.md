# cc-token-saver

> **Claude Code يقطعك باستمرار؟ ليس بعد الآن.**
>
> أنفق أقل، برمج لفترة أطول، واعرف بالضبط أين تذهب token الخاصة بك — بدون أي إعداد.

كيف؟ إدارة context تلقائية، تتبع تكاليف لحظي، وتحكم بالجلسة مع مراعاة cache — كل ذلك في إضافة واحدة.

خطة Claude Code Max ($200/شهر). يفترض أنها كافية. لكنها ليست كذلك.

**rate limit على نافذة 5 ساعات متدحرجة.** أنت في عمق كتابة الكود وفجأة يتوقف. لا مؤقت. لا وقت متوقع. فقط انتظر.

**كل شيء يدوي.** حجم context، توقيت انتهاء cache، تفويض SubTask، تنظيف session. لا أحد يستطيع تتبع كل هذا أثناء البرمجة.

## 🛡️ الميزة 1: Token Guardian

**يكتشف انتهاء صلاحية cache ويمنع تلقائيا إعادة الإرسال المكلفة.**

مدة صلاحية prompt cache في Claude Code هي ساعة واحدة. ابتعد لأكثر من ساعة وينتهي cache. رسالتك التالية تعيد إرسال كامل context بالسعر الكامل. عند 900K token، هذا $9 في طلقة واحدة.

Token Guardian يتتبع وقت آخر استجابة. إذا مرت أكثر من 3,590 ثانية (TTL ناقص 10 ثوانٍ احتياطية)، يمنع prompt ويعرض تحذيرا.

```
🚨 انتهت صلاحية الذاكرة المؤقتة (68د 23ث خمول)

انتهت صلاحية الذاكرة المؤقتة. المتابعة ستعيد إرسال كل السياق.
قد تزداد التكلفة بشكل كبير.

👉 /context — تحقق من استخدام السياق الحالي قبل اتخاذ القرار
👉 /clear → /continue — إعادة التعيين ثم استعادة السياق السابق (موصى به، أقل تكلفة)
👉 إعادة الإرسال — المتابعة كما هو (تكلفة إعادة التخزين المؤقت الكاملة تُتكبّد)
```

فقط أعد إرسال نفس prompt بعد التحذير — سيمر. التحذير يظهر مرة واحدة فقط لكل فترة خمول، فلا يزعجك أبدا. رسائل التحذير تُعرض بـ 23 لغة بناء على لغة نظام التشغيل.

**النتيجة:** تكاليف إعادة cache المكلفة تُمنع تلقائيا. لا يتطلب أي جهد.

## 🧠 الميزة 2: Smart Session Architecture

**ثبّته وستبدأ أنماط العمل المُحسّنة للتكلفة تلقائيا.**

معظم المستخدمين يفعلون كل شيء في session الرئيسية. قراءة الملفات، توليد الكود، تشغيل الاختبارات. كل مخرجات تتراكم في context وتُعاد إرسالها مع كل رسالة. الجلسة تتضخم. التكاليف تتصاعد.

Session Architect يحقن تلقائيا استراتيجية تفويض عند بداية كل session.

|                  | Main Session                      | SubTask                               |
| ---------------- | --------------------------------- | ------------------------------------- |
| الدور             | التصميم، القرارات، المراجعة         | التنفيذ، توليد الكود، ملفات متعددة  |
| مستوى cache       | ساعة واحدة (ephemeral_1h)             | 5 دقائق                                  |
| تكلفة كتابة cache | ＄10/MTok                          | ＄6.25/MTok                            |
| حجم context     | ~94K متوسط                          | ~33K متوسط                              |

SubTask لديها **كتابة cache أرخص بـ 37.5%** من Main. حجم context أيضا أصغر بكثير. تفويض العمل الثقيل إلى SubTask يخفض التكاليف بشكل كبير.

**النتيجة:** Claude يعمل تلقائيا بنمط موفر للتكلفة. لا تحتاج للتفكير في ذلك.

## 🔄 الميزة 3: /continue — استعادة Context

**يحل محل `/compact`. صفر استدعاءات LLM. صفر تكلفة token.**

`/compact` يرسل كامل context (~1M token) إلى LLM لضغطه في ملخص 3.3%. إذا انتهى cache، هذا وحده يُطلق إعادة cache كاملة. فقدان المعلومات أمر حتمي.

`/continue` يتبع نهجا مختلفا تماما. يعالج نص session السابقة مسبقا ويحمّله مباشرة. لا استدعاء LLM. لا تكلفة. المحادثة الأصلية تُستعاد كما هي.

|                         | /compact                          | /continue                        |
| ----------------------- | --------------------------------- | -------------------------------- |
| طريقة العمل            | يرسل كامل context إلى LLM للتلخيص | يعالج النص مسبقا، يقرأ مباشرة |
| استدعاءات LLM               | مطلوبة (عادة 100K+ token) | 0                                |
| تكلفة token              | عالية                              | 0                                |
| فقدان معلومات        | نعم (ملخص 3.3%)                | لا (الأصل محفوظ)        |
| سرعة المعالجة        | عشرات الثواني                   | < 1 ثانية (حتى ملفات 60MB+)       |
| عند انتهاء cache   | تكلفة إعادة cache كاملة فوقها         | لا تأثير                        |
| استعادة session متعددة   | غير ممكنة                      | مدعومة                        |

الاستخدام: `/clear` ثم `/continue`. ستظهر قائمة session السابقة. اختر واحدة للاستعادة. للاسترداد السريع: `/continue last`.

**النتيجة:** استأنف عملك السابق بتكلفة صفرية. بدون فقدان معلومات.

## 📈 لوحة الاستخدام (/usage-view)

**أخيرا أجب عن: "لماذا ضربني rate limit؟"**

حتى الآن، الوصول إلى rate limit كان يجعلك غاضبا فقط. لا طريقة لمعرفة السبب. أي session استهلكت أكثر token؟ متى ارتفعت التكاليف؟ ما الأنماط في استخدامك؟ كل شيء مخفي.

`/usage-view` يعرض كل شيء. لوحة HTML تفاعلية تفتح في المتصفح، تتيح لك تحليل أنماط الاستخدام وتتبع مصدر ارتفاع التكاليف. لا تبعيات خارجية. يعمل مستقلا. قابل للمشاركة كملف.

ما تتضمنه:

- اتجاهات التكلفة يوميا / ساعيا / حسب يوم الأسبوع — اكتشف متى تستهلك أكثر token
- تفصيل token (إدخال، إخراج، كتابة cache، قراءة cache) — اعرف ما يرفع التكاليف
- تحليل التكلفة لكل session — حدد المهام المكلفة
- خط زمني لنافذة 5 ساعات (مشتركو Max Plan) — تتبع محفزات rate limit
- تحليل ذكي بالـ AI — يفسر البيانات ويقترح تحسينات
- 23 لغة مدعومة (RTL مشمول؛ الرسوم البيانية/الجداول تبقى LTR)

```
/usage-view                  # كل الأوقات، كل المشاريع
/usage-view current          # نافذة 5 ساعات الحالية فقط
/usage-view last 7 days      # آخر 7 أيام
/usage-view locale ar        # العربية
```

## 💡 كيف يعمل Cache فعلا

Claude Code يرسل كامل تاريخ المحادثة إلى النموذج في كل استدعاء API. "استدعاء API" لا يعني "رسالة واحدة كتبتها." prompt واحد يُطلق استدعاءات أدوات داخلية — Grep، Read، Edit، Write — وكل واحدة استدعاء API منفصل. prompt واحد يمكن أن يسبب 10+ استدعاءات API بسهولة.

prompt cache يخفض هذه التكلفة بنسبة 90%. لكن cache له عمر محدد.

|                     | Main Session                          | SubTask                                |
| ------------------- | ------------------------------------- | -------------------------------------- |
| مدة cache           | ساعة واحدة (ephemeral_1h)                 | 5 دقائق                                  |
| كتابة cache         | ＄10/MTok                              | ＄6.25/MTok                             |
| قراءة cache          | ＄0.50/MTok                            | ＄0.50/MTok                             |
| عند انتهاء cache  | كامل context يُعاد إرساله بالسعر الكامل    | تأثير منخفض (context صغير)          |

حتى مع بقاء cache حيا، التكاليف تتراكم. إليك سيناريو متطرف لتوضيح الفرق.

### السيناريو: يوم برمجة كامل (3 ساعات صباحا → 2 ساعة غداء/اجتماع → 3 ساعات بعد الظهر)

الشروط: تسعير Opus 4، prompt واحد في الدقيقة، ~5 استدعاءات API لكل prompt (~300 استدعاء/ساعة).

#### ❌ بدون cc-token-saver

معظم العمل يحدث في Main session. حجم context ينمو بسرعة.

| المرحلة       | الوضع                         | حجم context               | التكلفة                                   |
| ----------- | --------------------------------- | -------------------------- | -------------------------------------- |
| صباحا 3س  | برمجة (غالبا في Main)           | 100K → 600K (متوسط 350K)    | 900 استدعاء × 350K × ＄0.50/M = ＄157.50  |
| غداء/اجتماع   | بعيد لمدة ساعتين                  | —                          | —                                      |
| العودة      | cache انتهت → إعادة إرسال كاملة      | 600K بالسعر الكامل            | 600K × ＄5/M + 600K × ＄10/M = ＄9       |
| العودة      | /compact (تلخيص)              | 600K → تُرسل إلى LLM        | 600K × ＄0.50/M + مخرجات الملخص = ~＄1.50 |
| بعد الظهر 3س | البرمجة تستمر (context يكبر مجددا) | 100K → 600K (متوسط 350K)   | 900 استدعاء × 350K × ＄0.50/M = ＄157.50  |
|             | الإجمالي                             |                            | ~＄326                                  |

> عند هذا المستوى من الاستخدام، ستصل غالبا إلى rate limit لنافذة 5 ساعات. **التكلفة سيئة، لكن المشكلة الحقيقية أن عملك يتوقف تماما. هذه هي اللحظة بالضبط التي ينطفئ فيها Claude Code.**

#### ✅ مع cc-token-saver

العمل الثقيل يُفوَّض إلى SubTask. Main يتولى التصميم/القرارات فقط.

| المرحلة       | الوضع                                    | حجم context                | التكلفة                               |
| ----------- | -------------------------------------------- | --------------------------- | ---------------------------------- |
| صباحا 3س  | برمجة (Main: تصميم، SubTask: تنفيذ) | Main 100K → 300K (متوسط 200K) | 900 استدعاء × 200K × ＄0.50/M = ＄90 |
| غداء/اجتماع   | بعيد لمدة ساعتين                             | —                           | —                                  |
| العودة      | ⚡ Token Guardian يمنع → /clear + /continue | —                           | ＄0 (لا استدعاءات LLM)                 |
| بعد الظهر 3س | البرمجة تستمر                             | Main 100K → 300K (متوسط 200K) | 900 استدعاء × 200K × ＄0.50/M = ＄90 |
|             | الإجمالي                                        |                             | ~＄180                              |

#### 💰 النتيجة

> **＄326 → ＄180. ＄146 وفر في اليوم (45%).**
>
> الأمر لا يتعلق بالتكلفة فقط. token أقل في نفس الوقت يعني **لن تصل إلى rate limit وتستطيع مواصلة العمل.** هذا هو الفرق الحقيقي.

### أين يتدخل cc-token-saver

```
[بدء الجلسة]
    │
    ├─ Session Architect → يحقن نمط تفويض SubTask تلقائيا
    │                       يبقي Main context تحت 250K
    │
[أثناء العمل]
    │
    ├─ Status Line → مراقبة لحظية للتكلفة/context/rate limit
    │                  تنبيه فوري عند دخول منطقة التحذير
    │
[خمول +1 ساعة]
    │
    ├─ Token Guardian → يكتشف انتهاء cache، يمنع قبل الإرسال
    │
[إعادة تشغيل الجلسة]
    │
    └─ /continue → يستعيد context السابق بتكلفة صفرية (لا استدعاءات LLM)
```

## 💡 نصائح

### افهم cache وستعرف أين يذهب المال

- **prompt واحد ≠ استدعاء API واحد.** في كل مرة يستدعي Claude أداة Grep أو Read أو Edit، يُعاد إرسال كامل context. prompt واحد يطلق 10+ استدعاءات API بسهولة. اكتب prompt واضحا لتقليل استدعاءات الأدوات غير الضرورية وخفض التكاليف.
- **مؤقت cache يُعاد من آخر استدعاء API، وليس من آخر prompt كتبتها.** واصل العمل ولن ينتهي cache أبدا. الخطر هو الابتعاد. Token Guardian يمنع تلقائيا مرة واحدة، فعند عودتك تختار: إعادة تعيين context أو المتابعة كما هو.
- **حجم context = مضاعف التكلفة.** نفس استدعاء API عند 200K مقابل 800K يكلف 4 أضعاف. عندما يتجاوز [CTX] في شريط الحالة 35% (🟡)، هذه إشارتك لتفويض أكثر إلى SubTask.

### عادات تخفض التكاليف

- **اجعل CLAUDE.md مختصرا.** يُحمّل في system prompt مع كل استدعاء API. كل سطر يكلف مالا.
- **فوّض العمل الثقيل إلى SubTask.** توليد الكود، تعديل ملفات متعددة، تشغيل الاختبارات لا تنتمي إلى Main. SubTask لديها context أصغر ومستوى cache أرخص.
- **بعيد لأكثر من ساعة؟** `/clear` → عد → `/continue`. context يُستعاد بتكلفة $0.
- **[5H] فوق 70% (🟡)؟** أبطئ. انتقل لمهام مراجعة خفيفة أو زد تفويض SubTask لتقليل عدد استدعاءات API في Main.
- **استخدم `/btw` للأسئلة الجانبية.** لا تدخل تاريخ المحادثة، فيبقى context مختصرا.
